## 1. 设计哲学

### 1.1 原生 AI 应用 = 三层职责清晰分离

```text
┌────────────────────────────────────────────────────────┐
│  PostgreSQL：唯一业务事实源（ACID 强一致）              │

                       ▼

└────────────────────────────────────────────────────────┘
```

### 1.2 与 V2.0-MVP 的根本区别

| 维度 | V2.0-MVP | V2.1（修订） |
|---|---|---|
| **AI 能力** | 页面助手 + 工具调用 | **原生 AI 应用**（编排 + 推理 + 确认） |
| **数据写入** | AI 可调工具直写 | AI **只生成 proposal**，人工确认后写 |
| **图谱** | 无 | **Neo4j 只读层** + 事件投影 |
| **状态机** | 22 状态直接写 | **统一状态字典** + 转换迁移 |
| **事件溯源** | 仅 `project_event` 简表 | **完整 `event` 表** + 事件投影 |
| **审计** | 缺失 | **不可变 `audit_log`**（所有关键操作） |
| **风险** | 数据丢失不可忽略 | **可清空重建**（数据派生层） |

---

## 2. 核心约束（写在前面的红线）

1. **PostgreSQL 是业务事实唯一来源** — 不允许 AI 写 Neo4j 后回写 PG
2. **Neo4j 是只读派生层** — 任何修改必须通过 PG → Event → Projection 链路
3. **AI 不直接写 DB** — 只能生成 `action_proposal`，经人工确认后由后端写入
4. **图谱可以清空重建** — Neo4j 是 cache，丢了从 PG 重新投影
5. **AI 不可用时业务不中断** — 纯人工流程必须完整可用
6. **数据丢失可忽略** — 系统未上线，所有测试数据可清空重建

```typescript
// graph/neo4j.client.ts
import neo4j, { Driver, Session } from 'neo4j-driver';

class Neo4jClient {
  private driver: Driver;
  
  async executeRead(query: string, params: object): Promise<any[]> {
    const session = this.driver.session({ defaultAccessMode: neo4j.session.READ });
    try {
      const result = await session.run(query, params);
      return result.records.map(r => r.toObject());
    } finally {
      await session.close();
    }
  }
  
  // 注意：Neo4j 只允许 READ 操作，不允许 WRITE
  async executeWrite(query: string, params: object): Promise<any> {
    throw new Error('Neo4j is read-only. Use Projection Worker to write.');
  }
}
```

#### 3.3 Projection Worker
```typescript
// graph/projection.worker.ts
class ProjectionWorker {
  async project(event: BusinessEvent): Promise<void> {
    switch (event.type) {
      case 'customer.created':
        await this.upsertCustomerNode(event.payload);
        break;
      case 'service_case.created':
        await this.upsertServiceCaseNode(event.payload);
        await this.createRelationship('Customer', 'ServiceCase', 'OWNS', ...);
        break;
      case 'service_case.status_changed':
        await this.updateServiceCaseStatus(event.payload);
        break;
      // ...
    }
  }
  
  private async upsertCustomerNode(c: Customer) {
    await this.writeToNeo4j(`
      MERGE (c:Customer {id: $id})
      SET c.name = $name, c.industry = $industry, c.updated_at = $updatedAt
    `, c);
  }
}

// 后台循环（也可作为独立进程）
async function projectionLoop() {
  const worker = new ProjectionWorker();
  while (true) {
    const events = await pg.query(`
      SELECT * FROM event 
      WHERE projected_at IS NULL 
      ORDER BY occurred_at ASC 
      LIMIT 100
    `);
    
    for (const event of events.rows) {
      try {
        await worker.project(event);
        await pg.query('UPDATE event SET projected_at = NOW() WHERE id = $1', [event.id]);
      } catch (err) {
        await pg.query(`
          UPDATE event 
          SET projection_attempts = projection_attempts + 1, 
              projection_error = $2
          WHERE id = $1
        `, [event.id, err.message]);
        
        // 超过 5 次失败 → 死信
        if (event.projection_attempts >= 5) {
          await pg.query('UPDATE event SET projection_status = $2 WHERE id = $1', [event.id, 'dead_letter']);
        }
      }
    }
    
    await sleep(1000);
  }
}
```

#### 5.2 AI 提取流水线
```typescript
// orchestration/extraction/extraction.orchestrator.ts
class ExtractionOrchestrator {
  async extract(inboxItem: InboxItem): Promise<ExtractionResult[]> {
    const input = await this.prepareInput(inboxItem); // 文件 OCR 或 文本
    
    const results = [];
    
    // 1. 实体匹配（客户 / 案件）
    const entityMatch = await this.matchEntity(input);
    results.push({
      type: 'entity_match',
      candidates: entityMatch.candidates, // 多个候选
      confidence: entityMatch.confidence
    });
    
    // 2. 字段提取（金额 / 日期 / 编号）
    const fieldExtraction = await this.extractFields(input, entityMatch.bestCandidate);
    for (const [field, value] of Object.entries(fieldExtraction.fields)) {
      results.push({
        type: 'field',
        field_name: field,
        extracted_value: value,
        confidence: value.confidence,
        evidence: value.evidence  // { document_id, page, quote }
      });
    }
    
    return results;
  }
  
  private async matchEntity(input: ExtractionInput): Promise<EntityMatchResult> {
    // 1. 明确 service_case_id
    // 2. 合同号/案件号
    // 3. 客户统一社会信用代码
    // 4. 客户名称精确匹配
    // 5. 客户名称模糊匹配
    // 6. 联系人/电话辅助匹配
    // 7. 多候选 → 人工确认
    const matches = [];
```

```typescript
class ProposalGenerator {
  async generateFromExtraction(extraction: ExtractionResult[]): Promise<ActionProposal[]> {
    const proposals = [];
    
    for (const result of extraction) {
      if (result.confidence < 0.7) continue; // 低置信度不生成 proposal
      
      if (result.type === 'field' && result.field_name === 'paid_amount') {
        proposals.push({
          action_type: 'CREATE_PAYMENT',
          payload: {
            amount: result.extracted_value,
            date: result.date,
            customer_id: result.entity_id
          },
          risk_level: 'high',  // 收款确认是高风险
          required_role: 'finance',
          evidence_ids: [result.evidence.document_id],
          expires_at: addDays(new Date(), 7)
        });
      }
      
      if (result.type === 'entity_match' && result.confidence < 0.95) {
        proposals.push({
          action_type: 'CONFIRM_CUSTOMER',
          payload: {
            candidates: result.candidates
          },
          risk_level: 'medium',
          required_role: 'sales'
        });
      }
    }
    
    return proposals;
  }
}
```

```typescript
// orchestration/risk-detection/risk.detector.ts
class RiskDetector {
  async detect(caseId: string): Promise<Risk[]> {
    const risks = [];
    
    // 超期未收款
    const overdue = await this.findOverduePayments(caseId);
    if (overdue.length > 0) {
      risks.push({
        type: 'PAYMENT_OVERDUE',
        severity: 'high',
        items: overdue,
        recommendation: '立即联系客户确认付款计划'
      });
    }
    
    // 资料缺口
    const missingDocs = await this.findMissingDocuments(caseId);
    if (missingDocs.length > 0) {
      risks.push({
        type: 'DOCUMENT_GAP',
        severity: 'medium',
        items: missingDocs,
        recommendation: 'AI 建议补充以下资料：' + missingDocs.join('、')
      });
    }
    
    // 阶段停滞（>30 天未进展）
    const stagnant = await this.findStagnantStages(caseId);
    if (stagnant) {
      risks.push({
        type: 'STAGE_STAGNANT',
        severity: 'medium',
        days: stagnant.days,
        recommendation: '案件在 ' + stagnant.stage + ' 阶段停滞 ' + stagnant.days + ' 天'
      });
    }
    
    return risks;
  }
}
```

## 4. 关键技术决策

### 4.1 Neo4j vs PostgreSQL 图查询

| 维度 | PostgreSQL | Neo4j |
|---|---|---|
| **优势场景** | OLTP 强一致 | OLTP 读优化 + 复杂关系 |
| **成本** | 低（已用） | 中（额外实例）|
| **运维** | 已有 | 新增 |
| **查询性能（>3 跳）** | 慢 | **快** |
| **可视化** | 弱 | **强** |

**结论**：使用 Neo4j 作为只读派生层，PostgreSQL 仍然是事实源。

### 4.2 Event Sourcing vs 直接 SQL

| 维度 | Event Sourcing | 直接 SQL |
|---|---|---|
| **审计** | 天然支持 | 需要额外日志 |
| **回溯** | 完整时间线 | 困难 |
| **投影** | 容易（事件流） | 需要全表查询 |
| **复杂度** | 高 | 低 |

**结论**：关键业务用 Event Sourcing，简单 CRUD 可以不用。

### 4.3 AI 不直写 vs AI 辅助

**AI 不直写**（V2.1 选择）：
- 安全、可审计、可回滚
- 增加 1-2 秒延迟
- 适合业务关键路径

**AI 辅助**（V2.0 当前）：
- 速度快
- 风险大
- 适合非关键路径（搜索、推荐）

**结论**：业务事实 → AI 不直写；推荐/搜索 → AI 可直接调工具。

## 5. 风险评估

| 风险 | 概率 | 影响 | 缓解措施 |
|---|---|---|---|
| Neo4j 同步延迟 | 中 | 低 | 后台进程 + 监控告警 |
